# Предварительное скачивание через Steamworks

Включается отдельно. Загрузчик поднимает анонимную серверную сессию Steam в отдельном процессе Windows x64 и создаёт новый кеш для каждого запроса. Нужны 64-битный Python 3.12+, `steam_api64.dll` из соответствующей установки Project Zomboid и совместимый Steam Runtime. Скрипт загрузчика уже внутри JAR. Сценарий проверен на Windows с установленным Steam Runtime.

Укажите отдельный Workshop-кеш выделенного сервера с существующим `appworkshop_108600.acf` после штатного запуска. Игра должна загружать работы из этого кеша. Локальные моды с теми же ID могут перекрывать их.

```properties
dryRun=false
stagingEnabled=true
stagingDirectory=staged-workshop
stagingWorkshopDirectory=C:/PZServer/steamapps/workshop
stagingPython=C:/Python313/python.exe
stagingSteamworksLibrary=C:/PZServer/steam_api64.dll
```

`stagingPython` задаётся абсолютным путём. Остальные пути могут быть относительными к конфигу. При переходе с 0.6.0 укажите два пути для Steamworks. Старый `stagingSteamCmd` игнорируется. На Linux предварительное скачивание через Steamworks пока недоступно, там можно оставить мониторинг с отключённым скачиванием.

Запускайте `tools/BeforeServerStart.ps1` при остановленном сервере перед каждым стартом, в том числе из панели. Скрипту нужны путь к конфигу Sentinel, server.ini и Java. Пример команды есть в [английской инструкции](STAGING.md). Храните скрипт и его JAR по стабильному пути вне заменяемого кеша. При ошибке подготовительного шага сценарий запуска должен завершиться.

Во время игры файлы скачиваются в отдельный кеш и очередь. Перед стартом Sentinel проверяет готовые файлы по SHA-256 и отдельно запрашивает актуальный manifest ID через свежий Steamworks-кеш. Если ID совпадает, можно применить подготовленную копию. Новый manifest, даже с той же датой, запускает повторную подготовку. Независимая сверка может скачать предмет целиком. Штатную проверку Workshop самой игрой оставьте включённой.

Размер и время установки из Steamworks сверяются с отдельным ACF. Manifest ID берётся из записи установленного предмета. Скачиваются только настроенные ID. Недоступный анонимно айтем, таймаут или расхождение данных блокируют применение. SHA-256 выявляет порчу подготовленных файлов.

Подготовительный шаг ведёт журнал замены каталогов и ACF. После прерывания он восстанавливает незавершённую транзакцию. Каталоги с фазой `PREPARED` сохраняйте до восстановления. Старые поколения очереди и завершённые резервные копии можно чистить при остановленном сервере. Блокировка рядом с рабочим кешем координирует экземпляры Sentinel. Другие программы её не учитывают.

Диагностика Steamworks в `steamworks-last-output.txt` внутри staging-папки. Лог применения в `WorkshopSentinel-prestart-*.log` рядом с конфигом.
