# Проверка WorkshopSentinel 0.4.10 — 2026-10-09

## Что поставляется

Один ID WorkshopSentinel и одна папка содержат Java bootstrap JAR, серверный Lua-мост, клиентскую проверку Workshop и обработчик MLOS. Единый EXE сохраняет исправленный механизм обновления файлов без переноса существующей папки.

## Проверки

- Gradle 8.7 / JDK 11.0.14.1: `build modZip` успешно; 25 поведенческих Java-тестов прошли. Игровые Java API в них представлены test doubles.
- В Kahlua/stdlib установленной игры выполнены клиентские Lua-тесты с подставными Steam API: активные моды и локальные исключения, дедупликация, первая точка отсчёта, сохранение кеша, изменения даты/версии, состояние NeedsUpdate, cooldown, неполный ответ без коммита, таймаут и поздний callback, nosteam, чтение ChangeLog, 201 работа пакетами 100/100/1 с паузами, очистка кеша и Unix timestamp roundtrip.
- UI doubles проверяют создание окна, выбор строки, экранирование rich-text, копирование и открытие ссылки, закрытие, одну кнопку меню, её видимость, закрытие при старте игры и тест окна без запросов Steam. Пиксели/нативный ввод этим не проверяются.
- Клиентские файлы сразу возвращаются при isServer=true без обращения к UI, Steam или Events.
- Существующие тесты MLOS с фактическим установленным Refr_utils.lua прошли.
- В публичных сигнатурах и байткоде установленной игры проверены SteamUGCDetails, querySteamWorkshopItemDetails, getModFileReader (version dir с fallback common), Clipboard, штатное меню/виджеты/ModOptions и OnPreUIDraw в UIManager.
- ChooseGameInfo подтверждает поля incompatible/loadModAfter, запятую как разделитель и удаление обратных косых черт. По страницам авторов обе работы 3756814990 и 3781306534 используют Mod ID ServerAutoUpdate_B42. В mod.info задан один конфликт с этим ID и необязательный порядок после ZombieBuddy/MLOS.

Клиентские тесты воспроизводятся через installer/test-client.ps1 с установленной игрой и JDK. Они не запускают игровой процесс.

## Механизм установщика

Сохраняется исправление 0.3.1: резервное копирование вне mods, обновление файлов без Directory.Move папки, сохранение конфигурации, восстановление заменённых файлов при сбое и отчёт с этапом/путём в TEMP. В предыдущей проверке воспроизведён отказ старой версии при запрете Delete только на папку; исправленная версия обновилась при той же ACL. Проверены read-only файл, блокировка JAR и восстановление содержимого. Рабочие ACL пользователя не менялись.

## Ограничения

Живой запрос клиента через Steam callbacks, реальный вид окна, сохранение из редактора и подключение игрока без единого пакета требуют игрового smoke-test. Штатные API проверены по установленному jar; tests doubles не доказывают живую интеграцию. Разделение исполнения Lua не подтверждает отсутствие требований к файлам/контрольным суммам при подключении. Загрузка JAR через ZombieBuddy, чат и экспериментальный QueueQuit не проверялись запуском сервера в этом обновлении. Dry-run и отключённый shutdown остаются настройками новой установки; реальная остановка не выполнялась. Публикации в Steam Workshop нет.

Чужой код и ресурсы Workshop Update Checker не включены. Клиентская функция реализована самостоятельно по описанию задачи и штатным API игры.

Подробности: [техническая справка](docs/TECHNICAL.md).
## Исправление загрузки 0.4.1

Клиентский console.txt показывает выбор .WorkshopSentinel-install-<temporary-id> вместо актуальной папки. Проверка файлов обнаружила две временные копии 0.3.0 с тем же ID и основную 0.4.0. Поэтому код новой кнопки не загружался. Новый установщик переносит только подтверждённый 42/mod.info таких временных копий в installer-backups, сохраняя содержимое и не меняя сторонние ID. В тестовой установке проверены отключение дубля, сохранность старого payload, резервная копия metadata и пропуск чужой staging-папки.

Предоставленный пользователем серверный DebugLog подтверждает Build 42.21.0, ZombieBuddy 2.3.4 как Java agent, выбор временной копии и сообщение Skipping server-only mod. В Java mod list WorkshopSentinel отсутствует; позднее Lua сообщает bridge missing. Ошибка происходит до подтверждения JAR. Ранняя проверка среды ZombieBuddy в этом запуске выбрала клиентскую ветку (в том же списке загружаются client/ JAR). Точная причина такого раннего результата внутри ZombieBuddy не установлена.

Путь javaJarFile заменён на media/java/WorkshopSentinel.jar. Main регистрирует bridge с явным alias и не запускает сервис. GameServer.server проверяется в Main.tick до любых операций конфигурации/логов/scheduler; на клиенте tick возвращается. Новый тест подтверждает регистрацию при false, отсутствие сервиса после клиентского tick и инициализацию только после смены флага на true. Политика ZombieBuddy/файл approvals не изменялись, одобрение автоматически не выдавалось. На клиенте с Java agent загрузка bootstrap теперь возможна; клиентский UI не требует его и работает отдельно. Исправленный серверный запуск ещё должен подтвердиться новым логом.
Локальный клиент обновлён исправленным установщиком: в <PZ cachedir>/mods осталась ровно одна обнаруживаемая запись WorkshopSentinel; два старых staging mod.info сохранены вне mods. Установленные metadata, JAR и клиентский UI совпадают с исходной поставкой по SHA-256. Игра не запускалась, ZombieBuddy approvals не изменялись. Сервер из предоставленного лога находится на другой установке и этим запуском установщика не обновлялся.

## Исправление кеша 0.4.2

Клиентский лог подтверждает регистрацию Java bridge и создание кнопки в 0.4.1, затем Cache writer unavailable. Байткод getFileWriter проверяет LuaManager.ALLOWED_FILE_EXTENSIONS и возвращает null до открытия файла при неподдерживаемом расширении. Имя .tsv заменено на .txt; табличный формат содержимого остаётся прежним. Nil writer обрабатывается обычным false/result, без Lua error внутри pcall. Результаты скана остаются в памяти, окно с изменениями доступно даже при отказе сохранения.

Lua-fixture теперь воспроизводит запрет неподдерживаемого расширения. Проверены .txt, nil writer без исключения, 201 результат при ошибке записи, автоматическое открытие окна при ошибке кеша и прежние сценарии сканирования/UI. Само сохранение из игрового процесса после исправления требует проверки следующего запуска. Серверный код в этом обновлении не менялся.
## Исправление русского интерфейса 0.4.3

Компилятор Kahlua из установленной игры сохраняет символы Lua-литерала в byte[] через i2b, затем декодирует буфер как UTF-8. Кириллица прямо в Lua теряла старшие байты и превращалась в символы со скриншота. Все 28 пар надписей вынесены в штатные UTF-8 Translate/EN/UI.json и Translate/RU/UI.json; интерфейс использует getText. Путь JSON подтверждён байткодом Translator.

Клиентские тесты исполняются компилятором игры. Независимые Java Unicode-строки проверяют реальные значения русского меню, заголовка и кнопок; проверена также английская ветка и наличие обоих переводов для запрошенных ключей. Прежний тест ошибочно сравнивал два повреждённых Lua-литерала. Проверены прежние сценарии модели и UI. Отрисовка после установки в запущенной игре пока не проверена; серверный код не менялся.

Партии 100 ID и пауза 4 секунды сохранены. Этот интервал выбран для WorkshopSentinel: публичное описание Workshop Update Checker сообщает о запуске кнопкой и не задаёт фиксированного автоматического периода.

Компактное окно 760x460 содержит список, детали и действия «Открыть Workshop», «Копировать ссылку», «Закрыть». Кнопка меню лишь показывает результат. Сигнатура обновлений предотвращает повторное открытие закрытого окна; новая ревизия снова вызывает уведомление. При обновлении списка сохраняется выбранный мод; пустой список имеет понятную подпись.

Тесты проверяют первый автоматический запрос, границу 20 минут, паузу в игре, возврат в меню, пустой список, таймаут и повтор по таймеру, дедупликацию уведомлений, отложенный popup, отсутствие запросов при открытии окна, три кнопки вместо четырёх, русский/английский текст и прежние сценарии Steam/cache. Нативный вид окна в игровом процессе ещё не проверен.

## Подпись ZombieBuddy 0.4.6

Steam-профиль i218 разрешён через публичный XML Steam в SteamID64 76561199013754121. Создан приватный PKCS#8 DER Ed25519 ключ вне проекта/поставки, в папке с отключённым наследованием ACL и доступом только текущему Windows SID. В поставке только публичный ключ и sidecar .jar.zbs. Локальный signing.local.properties содержит путь к ключу и исключён из Git/архивов.

Подписывается UTF-8 без BOM: ZBS:<SteamID64>:<sha256 lowercase>. Подпись проверена OpenSSL, затем реальным ZBSVerifier из установленного ZombieBuddy 2.3.4. Реальный верификатор принимает верную подпись, отклоняет другой hash и uploader ID. Публичный ключ для теста передан в in-memory author map; глобальные authors/config/approvals не изменялись, реальное доверие не выдавалось. После каждого JAR Gradle автоматически подписывает и помещает sidecar рядом с JAR при настроенном локальном ключе. Архив/EXE содержит эту пару; ключ в них отсутствует.

Публикация публичного ключа в Steam и подтверждение «доверять автору» на реальном клиенте/сервере ещё требуются. Подпись подтверждает конкретный JAR, не весь EXE или Lua. Подписанный JAR может быть отклонён до публикации ключа. Установщик проверяет копирование sidecar, инструкция содержит публичную строку; обхода политики ZombieBuddy нет.

По решению автора подпись выключена по умолчанию и в локальной конфигурации. Закрытый Steam-профиль не изменяется; ключ сохранён вне Git и поставки. Старые артефакты подписи из outputs перенесены в локальный work, вне репозитория.

Тест установки неподписанной версии поверх старого sidecar подтверждает перенос .zbs в installer-backups вне mods. Клиентский профиль, server.ini и пользовательский конфиг сохраняются. Обычное одобрение неподписанного JAR остаётся решением ZombieBuddy; approvals и политика доверия не изменялись. Сообщение установщика больше не предлагает изменение профиля при неподписанной установке.
## Исправление Java bridge missing — 0.4.8

Полученный серверный лог подтверждает одобрение JAR, вызов Main.main и регистрацию класса ZombieBuddy, но Lua bootstrap старой версии 0.4.5 сообщает Java bridge missing. Причина в нашем вызове exposeClass(Class, String): в ZombieBuddy 2.3.4 алиас, совпадающий с простым именем класса, приводит к удалению только что созданной глобальной переменной. Main теперь использует exposeClass(Class), без алиаса. Описание явного алиаса в предыдущем разделе относится к старой реализации.

Добавлен installer/test-bridge.ps1: runner исполняется игровым Java runtime с настоящими projectzomboid.jar и ZombieBuddy.jar. Тест воспроизводит удаление старого алиаса, проверяет наличие WorkshopSentinelBridge и выполняет его onTick из Kahlua. Только GameServer подменён тестовой заглушкой с server=false: сервер, scheduler, shutdown и изменения доверия не запускаются. PASS. Это проверка фактической регистрации и вызова, а не полного живого запуска dedicated server.

## Пустое serverIni — 0.4.9

Предоставленный отдельный лог подтверждает запуск scheduler с интервалом 300 секунд, optional-client адаптера и безопасного режима. Четыре проверки завершились AccessDeniedException до обращения к Steam: пустое serverIni= из поставляемого шаблона разрешалось в папку конфига. Обработка путей теперь использует fallback для отсутствующего, пустого и пробельного значения. Явные абсолютные и относительные пути сохраняют прежнюю семантику.

Регрессионный тест загружает настоящий поставляемый config/WorkshopSentinel.properties, выбирает Server/servertest1.ini и читает из него WorkshopItems. Также проверяет пробелы и явные пути. Серверные логи и личные пути пользователя в репозиторий не включены.

Проверки 0.4.9: 27 behavioral tests PASS, интеграционные тесты установщика PASS, регистрация и вызов Lua-моста настоящего ZombieBuddy 2.3.4 PASS. EXE/ZIP/JAR собраны без подписи; dry-run и запрет shutdown по умолчанию сохранены. Проверка Steam на живом сервере после этой правки ещё не подтверждена.

## Локальные моды и файловые ошибки — 0.4.10

MLOS-обработчик расширен на все установленные локальные моды. Проверены порядок ID, отсутствие фиктивных Workshop ID, обычные Workshop-записи, отказ при реально отсутствующем моде и повторная установка hook. Эти новые проверки используют MLOS doubles в установленном Kahlua runtime; живой редактор игры после расширения не проверен.

Клиент учитывает локальные версии отдельно от Steam и поддерживает локальные сканы без Steam. Проверены дедупликация mod ID со слешем/без, version change, cache roundtrip, отказ чтения метаданных одного мода, сохранение результатов при недоступном writer и сохранение memory baseline при отказе reader. Кнопки Workshop для локальных записей выключены и не создают URL. Клиентские тесты Kahlua PASS.

FailureReporter классифицирует AccessDeniedException, SecurityException, отсутствующий файл и неправильный тип пути; одинаковые ошибки группируются на десять минут с уведомлением о восстановлении. Проверены suppression, повторная диагностика после интервала, recovery, ошибка directory-as-ini и отказ подготовки маркера с последующим восстановлением. Ошибка маркера не разрешает shutdown. Ошибка файла лога допускает только console logging; недоступный конфиг не заменяется молча безопасными defaults (только NoSuchFileException). Политика доступа и доверия не изменена, чужие игровые исключения не перехватываются.

28 behavioral tests PASS; интеграционные тесты установщика (включая подсказки access-denied/locked-file и предыдущие rollback сценарии) PASS; реальный ZombieBuddy 2.3.4 bridge exposure PASS. Подготовлены неподписанные JAR, ZIP и единый EXE; safe defaults сохранены.
